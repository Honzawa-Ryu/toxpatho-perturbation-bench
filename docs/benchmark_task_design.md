# パッチレベル・マッチングベンチマーク タスク設計 (Draft v0.1)

- 作成日: 2026-08-19
- ステータス: ドラフト（要レビュー・合意形成前）
- 元インプット: 「★パッチレベルマッチングアルゴリズムの開発」方針共有メッセージ

## 1. 目的

WSI（Whole Slide Image）から切り出したパッチに対し、様々な foundation model / SSL model の埋め込みが

1. **摂動（perturbation）に対してどこまで不変か**
2. **同一タイプの病理所見をどこまで意味的に一致させられるか**

を定量評価できるベンチマークを構築する。2025年時点の病理 foundation model の retrieval Top-5 F1 が
高々 40% 程度に留まるという観測があり、「foundation model がカバーできる領域／できない領域」を
パッチ単位のセマンティックな切り分けとして可視化することが狙い。

評価対象モデルは **TRIDENT が対応する patch encoder 群**（提供元がWSIから複数モデルの埋め込みを
抽出して用意する想定）。データ（WSI・所見アノテーション）も提供元が用意する前提とし、本ドキュメントは
「どのようなタスクを・どういう入出力/指標で・どういう優先順位で作るか」の設計に絞る。

## 2. データソース（想定）

| ソース | 用途 | 備考 |
|---|---|---|
| TG-GATEs（thioacetamide 周辺） | メイン。Task A/B のコア | 塩野義提供の所見付き画像あり → Task B の正解ラベルに利用可能 |
| Eisai CCl4 | サブ／再現性確認用 | 別の肝毒性モデルでの汎化確認に使える |
| Web由来など異ソース画像 | Task C（クロスソース検証） | スキャナ・染色・圧縮特性がTG-GATEsと異なる想定 |

肝臓の所見なので、Task Bのラベル候補は TG-GATEs の所見語彙に準拠する形が扱いやすい
（例: necrosis / single cell necrosis, fatty change (steatosis), fibrosis, inflammation・cellular
infiltration, bile duct proliferation, hypertrophy, extramedullary hematopoiesis, regeneration 等）。
実際のクラス設計は提供データのアノテーション粒度に依存するため、データ到着後に確定する。

## 3. タスク全体像

| ID | タスク名 | 何を測るか | 正解ラベルの要否 | 優先度 |
|---|---|---|---|---|
| A | Perturbation Invariance（自己検索） | 同一パッチ由来の摂動画像を最近傍として引けるか | 不要（自己参照がGT） | Phase 1（今すぐ着手） |
| B | Semantic Finding Matching | 同じ病理所見タイプのパッチ同士が近傍にまとまるか | 必要（専門家所見） | Phase 2 |
| C | Cross-Source Matching | ソース（スキャナ・染色・圧縮）が異なる画像間でも同一由来／同一所見をマッチできるか | A相当は不要、B相当は必要 | Phase 1と並行で準備 |
| D | MPP Estimation リソース整備 | パッチ画像からMPP（実寸解像度）を推定できるか | 必要（メタデータ由来のGT） | Phase 1と並行で準備 |

方針メッセージにある通り、**A → B と直線的に進めるのではなく、A を進めながら C・D の
準備（データキュレーション・タスク設計）を並走させる**構成にする。

## 4. Task A: Perturbation Invariance（摂動不変性 / 自己検索）

### 目的
同一パッチ x に摂動 T を加えた T(x) が、埋め込み空間上で x 自身（および同一由来の他の摂動版）を
最近傍として引けるか。専門家アノテーション不要で即着手できる。

### Positive / Negative 定義
- Positive: 同一原パッチ x に対する複数の摂動版 {T₁(x), T₂(x), ...}
- Negative: gallery内の他パッチ（同一WSI内の別パッチ、または別WSI由来パッチ）
- Gallery サイズを振って、distractor数に対する頑健性も見られるようにする（例: 100 / 1,000 / 10,000パッチ）

### 摂動軸（案）

| カテゴリ | 摂動例 | 強度レベル |
|---|---|---|
| Photometric | brightness/contrast, H&E染色バリエーション（Macenko/Vahadane系のstain jitter）, color jitter, JPEG圧縮率 | 弱/中/強の3段階 |
| Geometric | 回転（90°刻み＋任意角度）, フリップ, 平行移動, 軽度クロップ, 弾性変形 | 同上 |
| Resolution/MPP | ダウンサンプリング, リサイズ（異なるMPP相当への変換）, ぼかし | 同上 |
| Noise/Artifact | ガウシアンノイズ, スキャナ的圧縮アーティファクトのシミュレーション | 同上 |
| Occlusion | 部分マスク, タイル境界ずれ（グリッドをずらして再サンプリング） | 同上 |

強度を段階的に振ることで、「どの摂動強度で不変性が崩壊するか」をモデルごとに曲線として比較できる
（単一の正解/不正解ではなく、劣化カーブとして評価する）。

### 評価指標
- Top-K Retrieval Accuracy（K=1, 5, 10）
- Recall@K, mAP
- Cosine similarity vs 摂動強度のカーブ（劣化率）
- Rank degradation（元パッチの順位がどれだけ落ちるか）

## 5. Task B: Semantic Finding Matching（意味的所見マッチング）

### 目的
異なる個体・WSI・条件（用量・時点）由来でも、**同じ病理所見タイプ**のパッチ同士が埋め込み空間で
近傍にまとまるか。専門家の所見ラベルが前提となる（塩野義提供データを利用）。

### 設計上の重要ポイント
- **同一WSI内マッチ vs 異なるWSI間マッチを分離して評価する。** 同一WSI内は染色・スキャナ条件が
  揃っているため簡単になりがちで、汎化性能を見るには異なる個体・用量・時点をまたいだマッチングが本命。
- ラベル粒度をどこまで細かくするか（所見カテゴリのみ／重症度grade込み／小葉内の位置(zonal
  location: centrilobular/periportal等)込み）は、提供されるアノテーションの粒度に合わせて確定する。
- クラス不均衡が強いと想定されるため（正常組織パッチが多数）、評価はクラスごとのprecision/recallも見る。

### 評価指標
- Top-5 F1（方針メッセージで言及されている既存指標。2025年時点の既存foundation modelで~40%という
  ベースラインと比較可能にする）
- mAP, per-class precision/recall
- kNN classification accuracy（埋め込みを固定してk近傍分類器を通した場合の精度）
- 定性評価: UMAP/t-SNEでの所見クラスごとのクラスタ可視化

---

## 6. Task C: Cross-Source Matching（準備フェーズ）

### 目的
TG-GATEs以外のソース（web由来病理画像、異なるラボ・スキャナの画像等）との間でも、Task A/Bと同様の
マッチングが成立するかを検証する。ドメインシフト（染色プロトコル・スキャナ特性・圧縮）への頑健性を見る。

### 今フェーズでやること（準備）
- 異ソース画像のキュレーション方針の検討（ソースメタデータ管理、ライセンス確認）
- Task A同様の自己検索評価をソース混在galleryで実施できる形にする
- 可能ならTask B相当（所見一致）もソースをまたいで評価できるようラベル対応を検討

---

## 7. Task D: MPP Estimation リソース整備（準備フェーズ）

### 目的
パッチ画像からMPP（micron per pixel、実寸解像度）を推定するタスクの評価リソースを整備する。

### 背景・関連性
- 異ソース画像はMPPメタデータが欠損・不整合なことが多く、これがTask Cのマッチング失敗要因になりうる。
- 多くのfoundation modelはMPP整合性を前提に学習されているため、MPP推定自体を診断用タスクとして
  切り出しておくと、A/B/Cの失敗要因分析（「意味理解の限界」なのか「解像度不整合」なのか）に使える。

### 今フェーズでやること（準備）
- MPPが既知のソースからのGTペア（画像 + 正解MPP）を集める
- 評価方法の案: 埋め込み経由の回帰 or 分類（MPPをbin分けして分類問題にする）

---

## 8. ロードマップ

```
Phase 1（着手可）        : Task A 実装・実行（摂動生成パイプライン、TRIDENT埋め込み取得、Top-K/mAP評価）
Phase 1と並行（準備）    : Task C のデータキュレーション方針検討 / Task D のGTリソース収集
Phase 2（データ到着後）  : Task B（専門家所見ラベルを用いた意味マッチング）
Phase 2以降              : Task C / D の本実装・評価
```

## 9. 評価対象モデル・埋め込みパイプライン

- WSI → パッチ抽出 → **TRIDENT** 経由で複数モデルの埋め込みを取得（提供元が準備）
- 評価対象モデルは当面 **TRIDENT に含まれる patch encoder 一覧**に準拠
- 参考として、単純な特徴量（色ヒストグラム等）やImageNet事前学習CNNなど非病理特化のbaselineも
  下限比較として含めるかは要検討（Open Questions参照）
